# Five-suite partial assertion-index maintenance

This maintenance-only workflow creates a source-addressed **partial index**.
It does not execute a renderer, run foreign tests, establish a semantic
assertion denominator, or grant a native assertion credit.

Create an isolated maintenance environment with the fixed parser versions:

```bash
python3 -m venv .venv-mermaid-assertion-index
.venv-mermaid-assertion-index/bin/pip install -r tools/mermaid/requirements-terminal-assertion-index.txt
.venv-mermaid-assertion-index/bin/python tools/mermaid/build_terminal_assertion_index.py --write-index
.venv-mermaid-assertion-index/bin/python tools/mermaid/validate_terminal_assertion_index.py
```

The generated index and its two input ledgers live together in
`tests/fixtures/mermaid_terminal/assertion_index/v3/`. The validator checks
that closure, the fixed parser package files, every referenced fixture source
file, every stored byte range, and the explicit unresolved records.

`contains` and `not_contains` rows carried from the audit are provenance-only
summaries. They cannot become direct semantic assertions because their labels
can differ from the source control flow (for example, a `strings.Contains`
condition whose expected branch is a miss). A later port must bind the complete
original function and branch/options contract before it can create a semantic
assertion record.

## Platform bound maintenance lock

The R3/R4 lock is intentionally exact for CPython 3.9.6 on Darwin arm64. It
hashes the installed `tree_sitter_rust/_binding.abi3.so`, which is a Mach-O
arm64 artifact. The validator rejects other Python versions, package versions,
or platforms rather than presenting them as equivalent. This restriction applies
only to this offline maintenance extractor; it adds no Loom production or native
test dependency. A portable maintenance workflow needs a separately reviewed
lock and regenerated byte-span fixture.

## V4 full declared-source maintenance closure

The v4 fixture at
`tests/fixtures/mermaid_terminal/assertion_index/v4_full_declared/` is a
separate, static source-identity closure. Its `full-declared-input.lock.json`
pins the reviewed R3, R4, and mmdflux-recovery package receipts, while
`input-closure.json` pins the four copied inputs and the durable-source
manifest. It retains the R3 source identities for 387 declared files and stores
generated rows against durable fixture paths.
It does not change v3, native test budgets, runtime expansion, semantic
coverage, or a five-suite denominator.

The 266 already-vendored source files retain their existing fixture paths. The
remaining 121 mmdflux originals are byte-for-byte durable copies under
`tests/fixtures/mermaid_terminal/mmdflux/full_declared_sources/<commit>/`.
Their `SOURCE_MANIFEST.v1.json` pins every upstream path, Git blob, byte count,
and SHA-256; the adjacent MIT license is copied and pinned too. The v4 source
map is a total bijection from the 387 R3 declared identities to durable paths.
The builder rejects a missing, duplicate, undeclared, non-fixture, digest-
mismatched, or build-cache path. It never falls back to the audit `build/`
directory.

Run the same locked maintenance commands against v4 after the reviewed parent
fixture inventory has been updated:

```bash
.venv-mermaid-assertion-index/bin/python tools/mermaid/build_terminal_assertion_index.py \
  --write-index \
  --fixture-root tests/fixtures/mermaid_terminal/assertion_index/v4_full_declared
.venv-mermaid-assertion-index/bin/python tools/mermaid/validate_terminal_assertion_index.py \
  --fixture-root tests/fixtures/mermaid_terminal/assertion_index/v4_full_declared
```

The validator rebuilds a temporary copy and requires byte-identical generated
output. It also verifies every durable source byte range, all 6,235 context
identities, 15,536 assertion-site entries, 15,390 distinct physical sites, and
2,412 mmdflux private-predicate bindings. Dynamic registrations, macros,
helpers, options, snapshots, and execution remain explicitly outside this
static maintenance result.

V4 accepts only the reviewed immutable R3/R4/recovery input bytes, audit
receipt records, durable manifest, and provenance-lock bytes compiled into the
maintenance extractor. The closure and lock repeat those values for audit
readability; they are not a self-authenticating replacement mechanism. Private
mmdflux predicate rows resolve to one retained AST context, and every repeated
physical source site is retained only when it is the proven Go parent/subtest
ancestor pair. These structural source checks do not convert any source record
into execution or semantic credit.

For a repeated physical assertion site, v4 requires the child context to be
an explicit Go `t.Run` subtest and its parent to be either a Go function or
another `t.Run` context, as well as retaining the parent identity and nested
body span. The adversarial suite parses a legal, newline-terminated forged R3,
lock, and closure before proving that fixed provenance constants reject their
self-consistent replacement. It separately rejects a corrupted assertion-site
byte range and a nested record whose declaration kind is not `t.Run`.
